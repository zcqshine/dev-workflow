# 项目教训文档：规范与模板

> 本文件是 dev-workflow 的**按需加载子文件**，是各项目教训文档的规范与模板。实际的教训记录在各项目的 `<项目>/.dev-workflow/lessons.md`，本技能目录不再存放实际教训。
> 权威规则在 SKILL.md 第 1 节（进化取用）和第 10 节（进化捕获与固化）。两者冲突时以 SKILL.md 为准。

## 核心规则（与 SKILL.md 一致）

1. 按项目隔离：教训记在 `<项目>/.dev-workflow/lessons.md`，每个项目一份；技能目录不放实际教训，避免跨项目信息污染。
2. 记录范围：本项目的所有教训都记，流程教训（怎么跑流水线更顺）与项目专属教训（框架和引擎的技术坑、测试命令、目录结构、编译运行陷阱等）都在范围内。每次运行最多追加 3 条，没有就不写。
3. 试金石只管固化，不管准入：判断一条教训去掉具体项目后，是否仍对“如何跑好 dev-workflow”有指导意义。是（如“评审 prompt 要自带长度约束”“SKILL.md 加载会截断”），固化时可并入 SKILL.md。否（如“本项目某框架的坑”），永远留在项目的 lessons.md 里，不并入 SKILL.md。

## 条目格式

```
- YYYY-MM-DD | 档位:全流程/轻量/技能完善 | 任务: <一句话> | 教训: <应怎么做、为什么> | 建议规则: <可并入 SKILL.md 的表述，无则写“无”>
```

## 项目教训文档骨架（新建 `<项目>/.dev-workflow/lessons.md` 时套用）

```markdown
# <项目名> dev-workflow 教训（只追加）

## 活跃教训

（条目按时间追加）

## 已固化（已并入 SKILL.md 的归档区）

（暂无）
```
