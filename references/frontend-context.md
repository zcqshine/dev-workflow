# 前端架构缓存：建档与刷新清单

> 本文件是 dev-workflow 的**按需加载子文件**。仅当任务涉及写前端代码、且需要新建/刷新项目架构缓存时读取。引用入口在 SKILL.md 第 6 节（Phase C）。
>
> 涉及两个产出：
> - **架构缓存**（项目级，跨任务复用）：`<项目>/.dev-workflow/frontend-architecture.md`
> - **任务上下文**（每任务落文）：`<项目>/docs/dev/<task-slug>/frontend-context.md`（轻量路径并入 `plan.md` 的"前端上下文"小节）

**任何前端代码动笔之前，先保证架构缓存新鲜。禁止缓存缺失或超期时跳过分析，直接按通用模板/个人习惯开写。**

## 1. 缓存命中判定（动笔前先做）

读 `<项目>/.dev-workflow/frontend-architecture.md`：

- 文件存在、头部有 `> 更新日期：YYYY-MM-DD`、且距今 ≤10 天 → **命中**：直接读取作为编码硬约束，跳到第 4 节写任务上下文，不重新盘点。
- 文件不存在、头部无更新日期、或更新日期距今 >10 天 → **未命中**：按第 2、3 节清单分析本项目，**新建或整体重写**缓存文件，头部记录今天的更新日期。

## 2. 架构缓存应包含的内容（分析时读文件确认，不要凭印象）

### 2.1 技术栈盘点

- **框架/版本**：React / Vue 2 / Vue 3 / Next / Nuxt / 原生 等，从 `package.json`、锁文件、`vite.config.*` / `webpack.*` / `nuxt.config.*` 确认。
- **关键依赖**：UI 组件库（Element Plus、Ant Design、Naive UI 等）、CSS 方案（Tailwind、CSS Modules、styled-components、Less/Sass）、状态管理、路由、请求库。**确认后必须沿用项目已选的库，不要为省事引入风格不一致的新方案。**
- **组件写法范式**：Options API 还是 Composition API、函数组件还是 class、`<script setup>` 等。

### 2.2 UI 设计风格盘点

- **组件风格来源**：项目用哪个组件库、是否有内部封装的通用组件目录（如 `src/components/`、`src/ui/`），**优先复用现有通用组件**而不是新造轮子。
- **布局体系**：栅格/间距规范、页面骨架（顶栏/侧栏/内容区）结构、响应式断点约定。
- **主题**：主色/强调色来源、暗色模式支持与否、字体/圆角/阴影等设计 token（如 `design tokens`、CSS 变量、Tailwind 配置里的主题）。
- **交互惯例**：弹窗（modal/drawer）用法、表单校验风格、空状态/加载态/错误态的统一呈现方式、动效节奏。

### 2.3 借鉴与参照

列出 1~2 个**功能相近的既有页面/组件**（含绝对路径），作为后续任务写代码时的对齐参照。

## 3. 缓存文件格式

```markdown
# <项目名> 前端架构与 UI 风格

> 更新日期：YYYY-MM-DD（超过 10 天需重新盘点刷新）

## 1. 技术栈
## 2. UI 设计风格（组件库/布局/主题 token/交互惯例）
## 3. 通用组件与参照页面（文件绝对路径 + 一句"新代码复用什么、对齐什么"）
```

分析中发现项目**没有统一前端风格**（混乱/空白）时，先在回复里向用户点明"该项目前端无统一风格，建议先定基础约定"，再继续；同时把这个事实记入缓存文件，避免下个任务重复发现。

## 4. 任务上下文（frontend-context.md）

缓存命中后，本任务的 `frontend-context.md` **不再重复全量盘点**，只写：

- **引用**：指向 `<项目>/.dev-workflow/frontend-architecture.md`，技术栈与 UI/UX 风格以缓存为准
- **本任务涉及的前端页面/组件/模块**：要新增、修改的真实路径
- **参照实现**：本次对齐缓存中哪个参照页面/组件，复用什么
- **缓存未覆盖的差异点**：本任务遇到的、缓存里没有的风格或约定（如有；这类点也值得回写进缓存）

## 5. 落文硬约束

分析完成后，写代码时**以架构缓存为硬约束**：组件库、样式方案、通用组件、设计 token 一律对齐项目现状；新增的页面/组件在结构与风格上要与参照物保持一致。

> 适用边界：流水线的 Phase C；若本次任务本身就是纯前端/纯 UI 改动（轻量路径直接写前端），同样在动笔前先做缓存命中判定，未命中先建档/刷新。
