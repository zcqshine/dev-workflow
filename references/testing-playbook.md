# 测试与判据设计 playbook

> 本文件是 dev-workflow 的**按需加载子文件**。进入 SKILL.md §8 测试阶段前读取。
> 权威门禁在 SKILL.md §8 第 4 条。本文件是“怎么做到”的详细清单，两者冲突时以 SKILL.md 为准。
> 本文件由 SKILL.md §8 下沉而来，内容未删减，只做分节、断行和排版润色。

## 1. 接口和 E2E 前置：先确认新代码真的在跑

- 构建和依赖安装都与服务生命周期互斥。服务运行时并行构建，会原地覆盖 classpath 产物。固定“停服务 → 构建 → 起服务”。
- 停服后确认端口监听进程归零。包装进程退出 ≠ fork 出的 JVM 退出，必要时按 PID 强杀。
- **重启后首个探针必须断言“只可能由新代码产生的值”**，否则整轮结论作废。
- 验证脚本要有防空跑出口，结尾断言“实际执行用例条数 ≥ 下限”。
  - 典型空跑：bash 调用未定义的 helper，只打一行 `command not found`，失败计数仍为 0，脚本却“全绿退出”。
- 会写库的脚本首部做三件事：环境护栏（生产拒跑）、残留清理、清理动作配判据。
- 一次性 E2E 脚本自带夹具、还原和残留判据。“造数 → 操作 → 复核 → 复原”四段都在脚本内，不许挪到脚本外靠人工 `psql`（复跑时无法证明前置状态）。
  - 夹具用带前缀的自建行（跑完按前缀删），不挑现成业务数据。
  - 取值断言用相对基线（`max(id)`、`count(*)` 差值），不用硬编码 id。
  - 结尾断言残留 = 0。
  - 实测两次翻车。复跑旧脚本因存量数据漂移大面积假红或假绿；复原段移出脚本后，复核判据读的是外部手工状态。

## 2. mock 盲区：哪些逻辑必须真实执行一次

守卫、删除保护、取数、计数、落库字段、口径、并发加锁这类**决定正确性**的逻辑，不得只停在 mock 协作对象后面，断言“方法被调用”或“返回固定值”。

会漏掉的三类：字段被 null 静默覆盖、SQL 别名大小写折叠致恒 null、加锁序跨行不一致。

必须有一次真实执行钉死：真实 DB 反向用例、断言落库实体字段终值、覆盖非默认形态与交错或边界输入。**单测全绿 ≠ 路径正确。**

### 2.1 必漏形态：“读旧值 → 改 → 比较/扣回”守卫

load-modify-save 里若在改脏实体**之后**才回读“改前值”，ORM 一级缓存返回的就是脏实例，“合计 − 原值 + 新值”退化成恒等式。**失效方向是越权多写。**

- 实测：比例编辑到 >100% 被放行。创建路径不传该参数，mock 单测无缓存语义，两边都看不见。
- 做法：改前值在 mutate **之前**捕获，并作参数传入；换键（换实体、换期间）后不许扣。
- 必须留一条真机编辑路径判据和一条变异探针（取值顺序改回旧写法，必须变红）。

## 3. 扫描型判据硬要求（对源码、文档、产物做正则或 AST 断言）

① “识别得出是它、却读不出内容”必须红，不许 `continue`。否则被扫对象换写法（别名、调用形态、改名）时，两侧同时看不见，等式照样成立。

② “集合 A ⊆ 白名单 B”而当前 A 为空的判据，收口前跑一次人为注入的变异探针，并在报告贴首条失败断言。只跑绿不能证明会红。

③ 变异探针自己也会假阴性。先断言“锚点命中数 == 预期”，≠1 时报告 SKIP 并打印命中数，不算“没红”。
  - 最常见失效是替换串根本没匹配（shell 吞引号、缩进或转义不符、锚点被 gofmt 改动），文件未变 ⇒ 误判“判据空转”，继而重写本来正确的守卫。
  - 跨语言或工具传参用文件式或 python 式替换，不用 `sed` 或 `perl` 内联变量。

④ “命中数 == 精确值”优于“>= 下限”。新增站点应当红，逼人复核；`>=` 会让漏接静默通过。

⑤ 处置表写“已加判据 X”前，必须当场跑 X（见 SKILL.md §1 实测铁律）。

⑥ 判据读“编译输入之外的文件”时（`os.ReadFile` 抓 migrations、配置、文档），测试缓存会假绿。新增被读文件后，用 `-count=1`（或等价参数）真跑一次，并把这条写在用例注释里。

⑦ 覆盖面自证：判据输入若来自“从文档挑出的表或条目清单”，清单本身要有单点来源与条数断言。漏圈一个同构对象（第二张必填表、第二类载体）时会一路绿到底。

## 4. 负向判据成对，断言前先确认载体

① 只写“伪造 X 应被拒”或“绝不出现 Y”，是单向断言。它常把正确行为判反：真正该断的是反面，把白名单改成合法来源后，伪造值必须仍被拒。每条负向判据配一条“应通过时确实通过”的正向哨兵，**两侧都会红才算判据**。

② 绝对表述（“全部不可见”“一律拒绝”）落笔前，每条查询和写路径都要找一次反例。

③ 先核实断言载体：
  - 响应 schema 里到底有没有该字段（建号响应往往是“一次性口令”形状，归属字段只在列表出参）
  - 列是 `NULL` 还是 `NOT NULL DEFAULT 0`
  - 路由是否真存在（不存在回 404，比断言业务码更强）
  - 首轮报红先逐条定性是产品错还是断言写错，并留实测证据。禁止顺手改产品代码附和错误的测试期望。

④ 判据在本步没有载体（端点未建、权限码未授、依赖步未跑）时，不得只登记“做不到”，要转写成一条“当前确实不可达”的负向判据。
  - 例：企业授予集没有这个码 ⇒ 断言企业打该端点必得 40300，且 message 来自权限网关。
  - 将来放开授权面时，它会变红要求补真用例。同时点名归属步骤与判据编号。
  - **只登记不做判据 = 护栏被悄悄拆除。**

⑤ “绿了”不等于“因正确的原因绿了”。反向用例只断业务码不够。参数校验或框架层常抢跑出同一个码（必填 400 与枚举非法 400 一样），载荷缺必填字段时整节集体“通过”。
  - 每条反向判据同时断言文案子串，写完做一次“故意让前置校验失败”自查。
  - 三条脚本假通过点（各实测踩过）：
    - 多个响应文件逐个解析：`cat a b | 解析器` 把两份 JSON 当一个，静默返回空，该节断言集体消失。
    - shell 捕获的 id 先做形态过滤：`psql -tAc "INSERT … RETURNING id"` 还会回显 `INSERT 0 1`。
    - 自建 helper 参数位错位，或 `except: pass`，会让判据空转照样绿。写完至少注入一次错值，确认会红。

## 5. 定性“与本次改动无关”的既有失败：stash 对照法

仅暂存本任务文件后，重跑相关测试类对照。

- `git stash push` 的 pathspec 混入 untracked 路径会整条静默失败。执行后必须用 `git stash list` 和 `git status` 双确认 stash 真实建立，再下结论。
- 对照完 `pop`，并核对文件数。
- pop 失败禁止原样重试：先读错误定位冲突文件（典型是被 dev、build 或 test 重写的自动生成文件，如 `components.d.ts`、`auto-imports.d.ts`），用 `git checkout --` 掉冲突文件再 pop。
- 每次 pop 后再双确认，防误弹或漏弹历史 stash。

### 5.1 推广：一切“临时改写他人或共享数据再还原”

适用场景：借账号口令做权限用例、临时补维度数据、改配置跑探针。

声称“已还原”不得只凭“按保存的值写回了”。保存清单可能因行序或同名值错位，必须加**外部对照**：

- 与本次从未改动的同态对象比对指纹（同批兄弟行的哈希、校验和）
- 断言临时值已不再生效（一次性口令登录必被拒、临时行计数归零）

## 6. 跨批次交界处补一次浏览器级判据

触发条件：本步只播种数据、放开身份，页面交互留给后续批次时，库里首次出现“半套状态”（有菜单无页面、有身份无落地页），既有守卫、剪枝、兜底第一次真正生效或失效。

为什么静态审查看不到：触发条件只在真实登录后的前端异步链（路由注册、菜单剪枝、幂等标志早退分支）里出现。静态审查、单测、HTTP 冒烟全看不到。

实测两次：

- 有菜单无页面 ⇒ 幂等早退连带跳过菜单剪枝，侧栏渲染 5 个死入口
- 放开新身份 ⇒ 登录第一跳 404、侧栏不渲染

做法：

- 本步改变了某前端守卫的输入集合形态，就收尾跑一次浏览器级探针（哪怕只是切号登录）。
- 跨模块失效登记 plan“执行偏差”，并指明归属步骤。
- 写幂等标志时检查“早退分支是否连带跳过了必须发生的赋值”，归一化收敛到唯一入口。
